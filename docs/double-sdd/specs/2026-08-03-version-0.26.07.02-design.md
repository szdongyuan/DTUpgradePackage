# 0.26.07.02 Version-Only Upgrade Design

## Objective

Add upgrade version `0.26.07.02`. This release performs no database, configuration, UI, AI, JSON-merge, or configured helper-executable operations. The existing main upgrade flow still replaces the deployed `DiTing.exe` from `resources/DiTing.exe` and then persists the new version.

## Design

- Add `resources/version_0.26.07.02.yml` using the existing manifest schema.
- Set `version` to `0.26.07.02`.
- Declare `db.sqls_operate`, `db.data_check.add`, `db.data_check.del`, `ai`, `ui`, `config`, `json_merge`, and `exe` as empty collections.
- Append `0.26.07.02` to `ALL_VERSIONS` in chronological order.
- Set `TARGET_VERSION` to `0.26.07.02`.
- Do not add `DiTing.exe` to the manifest's `exe` list. `main.update_version_program()` already copies `resources/DiTing.exe` to the parent application directory; a manifest `exe` entry would execute the program instead of replacing it.

## Error Handling

Existing upgrade orchestration remains authoritative. A missing or uncopyable `resources/DiTing.exe` continues to fail the main-program stage and trigger the existing rollback behavior.

## Testing

- Verify the manifest exists and contains only the version plus empty upgrade collections.
- Verify `0.26.07.02` is the final `ALL_VERSIONS` entry and equals `TARGET_VERSION`.
- Verify the main-program replacement remains outside the manifest and continues through the existing tested `update_version_program()` path.

## Compatibility / Migration

- Backward compatibility: required.
- Protected surfaces: version manifest schema, historical upgrade ordering, database/config upgrade behavior, main-program replacement behavior.
- Allowed breakage: none.
- Migration strategy: none; this is an additive version manifest and target-version advance.
